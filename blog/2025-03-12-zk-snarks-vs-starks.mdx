# ZK Proof Systems Compared

## 1. Core Differences

### 1.1 Trust Setup
- **ZK-SNARKs**: Require trusted setup (Toxic waste problem)
- **STARKs**: Trustless setup (No toxic waste)

### 1.2 Security Assumptions
- **ZK-SNARKs**: Relies on elliptic curves (pairing-friendly)
- **STARKs**: Relies on hashes (collision resistance)

## 2. Performance

### 2.1 Prover Time

# STARK prover (slower but parallelizable)
def prove_stark(computation, private_inputs):

    return generate_proof(polynomial_constraints)

## 4. Implementation

### 4.1 ZK-SNARK (Circom)
```circom
// Example: Prove knowledge of hash preimage
template Hash() {
    signal private input in;
    signal output out;
    
    // Constraints for SHA256
    // ...
    
    // Ensure output matches hash
    out <== sha256(in);
}

component main = Hash();
```

### 4.2 STARK (Cairo)
```python
%builtins pedersen range_check

from starkware.cairo.common.alloc import alloc
from starkware.cairo.common.crypto import hash as hash_func

def main():
    # Allocate memory
    let (data) = alloc()
    
    # Set input
    assert [data] = 12345
    
    # Compute hash
    let (hash) = hash_func(data)
    
    # Return hash
    return (hash=hash)
end
```

## 5. Use Cases

### 5.1 When to Use ZK-SNARKs

- Identity proofs
- Layer 2 scaling

### 5.2 When to Use STARKs
- High-value financial systems
- Post-quantum security
- Complex computations
