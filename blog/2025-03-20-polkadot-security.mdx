# Polkadot's Security Architecture

## Shared Security Model

### 1. Nominated Proof-of-Stake (NPoS)

```rust
// Simplified validator selection
fn select_validators(
    validators: Vec<Validator>,
    max_validators: u32,
) -> Vec<Validator> {
    validators
        .into_iter()
        .sorted_by_key(|v| Reverse(v.bonded_amount))
        .take(max_validators as usize)
        .collect()
}
```

### 2. GRANDPA Finality

- Finalizes blocks in batches
- 1/3 Byzantine fault tolerance
- Fast finality (12-60 seconds)

## Parachain Security

### 1. Collator Nodes

```rust
// Collator responsibilities
impl Collator {
    fn propose_block(&self) -> Block {
        // 1. Gather transactions
        let extrinsics = self.pool.ready();
        
        // 2. Create candidate
        let candidate = Candidate {
            parachain_id: self.para_id,
            relay_parent: self.relay_parent,
            extrinsics,
            // ...
        };
        
        // 3. Sign and broadcast
        let signature = self.key.sign(&candidate.hash());
        self.network.broadcast_candidate(candidate, signature)
    }
}
```

### 2. Availability & Validity

- **Availability**: Data is published
- **Validity**: State transitions are correct
- **Backing**: 2/3 of validators must approve

## Security Best Practices

1. **For Parachain Developers**
   - Implement proper weight calculations
   - Use bounded execution
   - Test with zombienet

2. **For Validators**
   - Use HSMs for key management
   - Monitor node performance
   - Stay updated with client releases

3. **For Nominators**
   - Diversify nominations
   - Monitor validator performance
   - Use proxy accounts
